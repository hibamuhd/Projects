# Limitations

This project is a portfolio/learning exercise built on a public dataset. It is **not** based on proprietary data from Blinkit, Zomato, Zepto, or any real company.

## 1. No real delivery-time or price data
The public Instacart dataset contains no delivery timestamps, delivery duration, or price/revenue fields. Any "delivery time," "AOV," or "revenue" metric in this project's delivery-analysis pages is built on the **explicitly synthetic** dataset generated by `python/06_generate_synthetic_delivery.py`. It is:
- Statistically plausible (peak-hour slowdown, basket-size correlation) but **not real operational data**
- Clearly flagged with `is_synthetic = 1` in every table/measure it touches
- Never merged silently into the "real" processed tables

## 2. Cohort methodology is tenure-based, not calendar-based
Instacart provides no absolute order date — only relative sequence (`order_number`) and days-since-prior-order. A calendar-month cohort matrix (e.g. "Jan 2025 cohort") is therefore **not derivable** from this dataset without fabricating dates. This project instead uses a tenure-based cohort: all users are grouped at their first order, and retention is tracked across order sequence number (order 1 → 2 → 3 ...). This is a standard, defensible substitute and is documented as such — not silently swapped in.

## 3. No fabricated results
No dataset numbers, retention percentages, reorder rates, or "insights" are pre-filled anywhere in this repo (see `INSIGHTS.md`). All such figures must be generated by actually running the pipeline against the downloaded dataset — this repo ships the *method*, not invented outputs.

## 4. Segmentation thresholds are heuristic
Customer segments (one-time / occasional / repeat / high-frequency) are defined using order-count quantiles computed from the actual data at runtime (see `python/03_feature_engineering.py`), not arbitrary fixed cutoffs chosen in advance. Document the actual quantile cutoffs you get once you run it — they will vary slightly depending on the exact date the dataset was pulled and any preprocessing choices.

## 5. No experiment results exist
product experiments describes **hypothetical** experiments that could be designed and not experiments that were actually run.
